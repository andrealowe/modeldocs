This document captures what has been built, key architectural context, and the gaps that remain before production deployment.

## What Was Built

### UI Changes
- Domino logo height increased to `40px`; Template label matched to Context sources label style
- Model banner colors updated to Domino design system: `#EDECFB` background, `#C9C5F2` border, `#3B3BD3` left accent
- Notebook buttons changed from vertical stack to horizontal `flex-direction: row`; "View in Workspace" → "Workspace"; Refresh button changed to `secondary` style

### Report Generation Fixes
- **Bold body text:** CSS overrides prevent mammoth from rendering all body text as bold; table cell bold preserved
- **Section title leaking into body:** Builder now checks `result.plan.title` and `result.plan.name`, handles `:` / ` —` / ` -` / `\n` separators
- **Key Findings ordering:** LLM prompt enforces: Key Findings bullets → narrative → visuals → tables → Recommended Actions
- **Callout styling:** Key Findings = lavender `#E8EBF9` / `#1F4E79` border; Recommended Actions = green `#E2F0E8` / `#2E7D32` border
- **Paragraph length:** Prompt enforces 1–2 paragraphs per section, 2–3 sentences each
- **Charts with no MLflow metrics:** `_generate_chart()` falls back to numeric hyperparameters or feature group counts
- **Code line numbers:** Citations include `lines N–M` when `start_line`/`end_line` are available

### Demo Report
Pre-built compliance report (`NBT-CR-EL-007_Compliance_Report_v7_0.docx`) covering all 10 sections with navy headings, callout boxes, data tables, and 4 embedded matplotlib figures. Generated by `auto_model_docs/build_demo_report.py`.

Companion notebook (`uploads/NBT-CR-EL-007_Compliance_Report.ipynb`) contains section headers, tables as `pd.DataFrame` cells, and the four figures as runnable matplotlib code — no prose.

### Demo Mode App Integration
`MODELDOCS_DEMO_MODE=true` (current default) intercepts Generate Documentation: shows a RUNNING row, transitions to SUCCEEDED after 15s, no real job or LLM calls. Controlled by the `MODELDOCS_DEMO_MODE` env var.

Four demo routes in `studio/routes_api.py`:

| Route | Purpose |
|---|---|
| `/demo/report-render` | Pre-built `.docx` as HTML via mammoth |
| `/demo/report-markdown` | Pre-built `.docx` as Markdown |
| `/demo/report-docx` | Download pre-built `.docx` |
| `/demo/report-ipynb` | Download pre-built `.ipynb` |

Demo files live at `auto_model_docs/studio/demo/`; `_ensure_demo_files()` regenerates them at startup if missing.

## Architecture Overview

```
User browser
    │
    ├── FastHTML app (web_app_studio.py) — runs on port 8889 in Domino notebook proxy
    │       ├── Inline YAML template editor (textarea, pre-filled server-side)
    │       ├── Model context banner (modelId + modelVersionId from query params)
    │       ├── Output format selector (Word/Markdown/LaTeX — UI only, not yet wired)
    │       └── Generate Docs button → POST /run
    │
    ├── /run (routes_job.py)
    │       ├── In demo mode: skipped — JS intercepts and shows mock output
    │       ├── Saves inline spec YAML to Domino dataset (timestamped file)
    │       └── Submits Domino Job with spec_path pointing to saved file
    │
    └── /api/* (routes_api.py)
            ├── /api/hardware-tiers
            ├── /api/datasets
            ├── /api/template-content?name=compliance|default
            ├── /demo/report-docx  → serves studio/demo/*.docx
            └── /demo/report-ipynb → serves studio/demo/*.ipynb
```

## Known Gotchas

- **FastHTML router and dots in paths**: Routes like `/demo/report.docx` silently 404 — use hyphens: `/demo/report-docx`.
- **Demo mode detection**: Domino URL looks like `/r/notebookSession/<id>/proxy/8889/`. JS uses `.indexOf('/notebookSession')` (not a tight regex).
- **Inline spec flow**: JS sets `spec_path = "__inline__"` and sends `spec_content` in the POST body. `routes_job.py` saves it as `_inline_spec_<timestamp>.yaml` before submitting the Domino job.
- **Environment validation**: `validate_studio_domino_compute_environment()` returns `[]` silently when env vars aren't set (dev/preview). Prevents a blocking error banner in local dev.
- **"Domino experiments" not "MLflow experiments"**: Intentional throughout the UI — don't revert.
- **Callout box colors in HTML viewer**: A JS post-processor applies inline styles after render. Applies to both demo and real reports via `_docx_to_html_response()`.

## Production Readiness Gaps

The demo mode skeleton is intentional; the gaps below are the delta to a real deployment.

### 1. Demo Mode Default

**Problem:** `MODELDOCS_DEMO_MODE` defaults to `"true"` in `studio/scripts.py:1163`. A mis-configured production deployment would silently serve fake output.

**Fix:** Change the default to `false`. Add a visible startup warning if the var is not explicitly set.

---

### 2. Real Job Submission

**Problem:** The web UI calls `_submit_local_job()` (`job_engine.py:270`), which spawns a local `asyncio` subprocess — not a Domino job. No isolation, no hardware tier enforcement, no tracking, no restart on crash.

`submit_job()` already exists in `domino_client.py:520` and calls `POST /v4/jobs/start` but is never invoked from the web UI.

**Fix:** Replace `_submit_local_job()` with `domino_client.submit_job()`, passing:
- Command string from `_build_job_command()` (`job_engine.py:177`)
- `overrideHardwareTierId`, `environmentId`, `environmentRevisionId` from `job_request` (currently accepted but ignored)
- `mainRepoGitRef` for the target project branch

---

### 3. Output Storage — `/tmp/modeldocs`

**Problem:** Job outputs are written to `/tmp/modeldocs/{project_id}/` (`routes_job.py:97`). `/tmp` is ephemeral, per-container, and shared across projects.

**Fix:** Write to a Domino Dataset mount path resolved from `DOMINO_DATASETS_DIR`, scoped per project. `AUTODOC_DATASET_NAME` (`dataset_manager.py`) already names the target dataset.

---

### 4. Code Root Resolution

**Problem:** When `browse_code` returns no repositories, `code_root_options_from_browse_response()` (`domino_client.py:214`) fell back to `/mnt/code` — the App's own source, not the target project's.

**Fix:** Require a valid `browseCode` API response. Fail with a user-facing error if no repository locations are returned.

**Partial progress:** Fallback now defaults to the first repository returned by `browse_code` rather than `/mnt/code`. The hard-code is gone, but failing loudly on empty response is still unimplemented.

---

### 5. MLflow / Experiments Context

**Problem:** `MLFLOW_TRACKING_URI` is never validated at startup — if unset, MLflow silently uses a local file store. `DOMINO_PROJECT_ID` filters MLflow artifacts by the App's own project, with no way to target a different project.

**Fix:**
- Validate `MLFLOW_TRACKING_URI` at startup; warn or block job submission if unreachable.
- Pass the target `projectId` through to the job command so the scanner filters by the correct project.

---

### 6. Environment Variable Validation

**Problem:** No startup check for required env vars. Failures only surface deep in job execution.

| Variable | Used for |
|---|---|
| `DOMINO_API_HOST` | All Domino API calls |
| `DOMINO_API_PROXY` | API proxy in App container |
| `DOMINO_PROJECT_ID` | MLflow filtering (must match target project) |
| `DOMINO_DATASETS_DIR` | Job history database and output storage |
| `MLFLOW_TRACKING_URI` | Experiment scanning |
| `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` | LLM calls (one required) |
| `MODELDOCS_DEMO_MODE` | Should be explicit, not defaulted |

**Fix:** Add validation in `_on_startup()` (`web_app_studio.py:1052`) and surface missing vars in the existing warnings banner.

---

### 7. Multi-Tenant Isolation

**Problem:** Job history SQLite DB at `{DOMINO_DATASETS_DIR}/{DOMINO_PROJECT_NAME}/modeldocs.db` is scoped only by `owner_id` + `project_id` query params — client-supplied values not fully server-verified.

**Fix:** Verify `project_id` membership server-side. Consider one DB file per project.

---

### 8. Job Status Polling

**Problem:** Real-job status is tracked by `_drain_process()` (`job_engine.py:250`) watching a subprocess. Once replaced with a real Domino job, this no longer applies.

**Fix:** Poll `GET /v4/jobs/{run_id}/status` from `domino_job_store._refresh_active_rows()`. `get_job_status()` already exists in `domino_client.py`.

---

### 9. Inline Spec Validation

**Problem:** Inline spec YAML is written to `/tmp/_inline_spec_{timestamp}.yaml` (`routes_job.py:113`) without schema validation. Errors only surface deep in the job subprocess.

**Fix:** Parse and validate against `DocumentSpec` before writing. Return a 400 with the validation error.

---

### 10. Compliance Template Enforcement

**Problem:** No server-side check that a submitted spec matches the compliance template's required sections.

**Fix:** After gap 9, verify required section names from `compliance_report_spec.yaml` are present in the submitted spec.
